--- COMPORTAMENTO OBSERVADO ---
1. O driver ABRE o /dev/mali0 real (kbase) e fala os ioctls do kbase
   (strings no binário: CS_GET_GLB_IFACE, CS_QUEUE_GROUP_CREATE,
   CS_TILER_HEAP_INIT, CS_QUEUE_KICK; fallback para /dev/dri se kbase
   estiver ausente).
2. NÃO usa root: roda como usuário comum (as permissões de /dev/mali0
   são 0666 system:graphics — apps normais têm acesso, igual um jogo).
3. Inicialização rápida (~23 ms total p/ instance+device); lib ~18 MB;
   shaders compilam na hora do pipeline (SPIR-V -> NIR -> instrução Mali),
   com bitmask de "cores" configurável (compute.core.mask / fragment.core.mask).
4. A warning "not well-tested on v7" indica que Mali-G52 (Bifrost v7) NÃO
   é a rota principal do driver (o foco são Bifrost/Valhall modernas, G57+),
   então crashe/bug visual é mais esperado nessa geração.
5. O fork expõe knobs via propriedades vendor.mesa.*, incluindo
   "force.vk.vendor" e "force.vk.devicename" — ou seja, dá pra "rebaptizar"
   a GPU reportada (spoofing de nome) — recurso clássico desses mods.
